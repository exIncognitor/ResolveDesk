# ResolveDesk 第三轮目标提示词

请在 D:\desktop\实习\ResolveDesk 自主推进第三轮有明确边界的开发目标：多轮纠错稳定性与知识库深度。完成开发、测试、部署、GitHub四项检查和证据记录后停止，不无限扩展。

固定范围：
1. Python是唯一后端，保留Vue、PostgreSQL、Redis、Chroma、MCP、Prometheus与Docker；不增加Java、业务领域或新的基础设施。
2. 基线固定为 f09efe7f25fe8028f2df97ef39b989bfd97212b0。第二轮112/100/12冻结集、原标签、知识及失败报告保持不变，仅作历史回归；不得围绕旧题补关键词或改评分。新建开发数据与独立冻结验收数据，在优化前固定新数据、知识、评分、模型配置及摘要。
3. 仅用deepseek-flash，读取唯一PostgreSQL累计账本；总额20元保留2元。本轮新增真实API费用另设3元上限，取更严格限制，不新建/重置账本、不重放不确定付费步骤。免费测试先行。adaptive策略继续关闭，不比较专用重排模型，不发送外部通知或配置外部告警。
4. 遵守项目AGENTS.md，修改前检查状态并用Git检查点保留版本；保护用户改动、数据库、凭据、模型和既有备份；不清理先前受限的测试目录。不要自行新增子代理、自动化或无限目标。

工作包一：多轮实体与任务稳定性
- 先复现并区分实体状态断言、最终草稿、实际业务状态和评测契约，不把状态缺失直接说成业务执行错误。
- 沿当前入口改进通用实体提取与合并：中文/阿拉伯/全角数字的明确使用天数、否定与更正、字段独立修改、多候选歧义、资源替换、取消旧任务与跨域切换。
- 所有写申请字段保留用户原文依据及轮次；拒绝推测身份、权限、产品或期限。不允许模型绕过草稿确认、审批、自批限制或租户/所有者隔离。
- 保留同轮幂等、版本冲突和既有权限/设备维修/软件授权三个流程。
- 新增不少于60条开发实体样例；优化前冻结不少于80条独立实体验收样例、12组多轮状态序列和至少8组可执行的真实Agent多轮验收。预先写清每轮实体、来源、任务边界、草稿/确认状态及最终业务断言。知识、测量与执行版本分开记录。

工作包二：有来源的知识内容与治理
- 在现有8篇模拟知识之外，新增至少24篇有明确官方来源的技术排障/安全操作手册，覆盖四类IT业务；以自写摘要、步骤与来源链接呈现，不整站复制，不冒充企业制度或生产数据。
- 建立来源、材料类型（技术参考/模拟制度）、适用系统/版本、审核/发布状态、生效/到期时间等元数据。沿现有内容版本、ACL、SQL/Chroma outbox与缓存失效机制实现，不能弱化它们。
- 支持草稿、审核发布和撤回；普通检索/引用/缓存不得返回未发布、已撤回或到期材料；权限与发布判断以SQL当前状态和数据库时钟为准。保留旧文档、内容与已有对话兼容，不删除用户资料。
- 提供与现有Vue工作台一致的轻量治理入口，能查看来源、适用范围、版本和发布状态；审核/撤回由获授权的人通过接口执行，模型只能读取。
- 新语料先固定，另冻结至少80条检索验收题，覆盖相似症状、版本差异、错误码、不足依据、材料过期/撤回和跨身份访问。相同语料下比较基线与候选的Recall@K/MRR、引用/来源有效性、拒答与发布边界，报告合成数据限制，不冒称生产质量。

- 分别汇报已实现、已验证、效果证据及剩余限制，记录Git恢复点、原始报告和实际累计/本轮API费用。达到固定范围后结束目标。
