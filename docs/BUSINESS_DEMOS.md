# 三条模拟业务演示与面试讲解

从 [当前架构](CURRENT_ARCHITECTURE.md) 开始。以下操作会创建明确的本地模拟工单；聊天会调用 Flash，正式执行前确认预算和使用自己的 Key。例句是公开演示材料，不作为新的盲测成绩。第四轮冻结验收使用另外固定的输入，原始结果在 `reports/iteration4-*-live-r*.json`。

## 共同准备

打开 `http://127.0.0.1:8080` 或 Docker 网关 `http://127.0.0.1:18080`。在设置填本地 `.codex-runtime/access.json` 对应的 learner 令牌；审核人使用 support 令牌。令牌只保留本机，不提交到 Git。知识页应有当前已发布材料；首次安装导入的是草稿，要先由 support 补齐发布信息并审核。每条独立流程点“新会话”。命令行可用 `python -m resolvedesk.cli --base-url http://127.0.0.1:18080 --actor learner`，`:new` 新会话、`:confirm VERSION` 确认核对过的草稿。

## 一、权限申请：生成计划和实际开通的区别

1. learner：“帮我准备仓库访问申请，先告诉我需要提供什么。”应追问资源、级别、天数；任务为 `awaiting_input`，没有建单。
2. “repo-resolvedesk，read，五天，用于学习后端接口，请准备草稿。”核对显示的三个字面字段，状态为 `awaiting_confirmation`。此时既无工单也无权限。
3. learner 点击确认，得到 `RD-...`，业务状态 `pending_approval`。重复同一确认应返回同一张单。
4. 切换 support，在业务工单操作 `approve`；状态为 `approved`，尚未有有效权限。再执行 `provision`，状态 `fulfilled`，learner 目录中出现期限从开通时算起的 read 权限。
5. 回 learner 同会话问“刚才那张申请现在处理到哪一步”，应读取已有单，不创建新单。新申请开新会话。

初学者讲法：大模型帮助理解和收集信息，服务端决定合法参数和能否写入。确认、审批、开通是三个不同动作。

进阶追问：SQL 事务如何防止只建工单不建业务记录？批准与开通为什么分开？旧版本、重复点击、同人审批如何拒绝？答案分别从 `Store.confirm`、`BusinessService.materialize/transition`、版本及幂等审计解释，不声称已集成真实 IAM。

## 二、设备维修：资产占用与返工

1. learner 查询本人资产和保修，应实际读取 `LT-1001`，无需知识充分性作为前置条件。
2. “准备本人 LT-1001 维修草稿，键盘卡键，已尝试外接键盘仍未解决。”核对资产、描述、标题后确认。
3. support 依次 `triage → assign → start → resolve`，派给 support。资产在未完成维修期间不可被另一条维修重复占用。
4. learner 认为未解决，`reopen` 回 `in_progress`；support 再 `resolve`；learner `accept` 后 `closed`，资产恢复 `available`。
5. 旁路演示只使用独立新会话：“设备冒烟，请转人工处理。”应说明安全和人工交接边界；没有真实人工队列，不能声称已完成维修或已自动创建工单。

初学者讲法：这是有状态的协作流程，不是回答一段维修建议。模型不能代替用户验收。

进阶追问：对资产的并发申请如何互斥？返工为什么保留工单和审计？版本冲突如何处理？从事务中的资产状态检查、有限状态转换、动作回执解释。

## 三、商业席位：预占和分配

1. 新会话问“商业 IDEA 授权审批要求是什么，只咨询不申请。”应有当前可读的模拟制度引用，不能产生申请草稿。
2. 新会话：“准备 IntelliJ IDEA Ultimate 席位申请，用于 Java 开发，使用九天。”模型必须使用明确商业版本和期限，不可猜天数。
3. learner 确认后由另一 support `approve → reserve → allocate`。预占有效 15 分钟；分配后按申请天数到期，目录库存满足 `总数=可用+预占+已分配`。
4. learner 或有权 support `revoke` 回收，或到期后由现有回收机制处理；不能把模拟席位当作厂商真实许可证。

初学者讲法：申请有同意、分配有库存、操作有权限，模型只负责草稿。

进阶追问：为什么先 reserve 再 allocate？如何防止超分配？过期、重复动作和取消如何返还库存？从 `resolvedesk/licenses.py` 产品锁、事务、期限和动作幂等解释。

## 讲项目时可展示的证据

展示一次输入、逐轮状态/字段来源、实际工具轨迹、确认前后数据库差异、工单操作审计及最终库存或资产状态。说明合成数据、当前规模、保守拒答、未接外部系统与外部告警的限制。面试中的技术解释应对应当前代码；过去版本的通过率和受控延迟不能作为当前生产表现。
