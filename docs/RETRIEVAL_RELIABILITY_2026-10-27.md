# G06 检索与工具可靠性验收

日期：2026-10-27。固定范围为审计R04/R05/R07及G06；G07–G11和其他包剩余项仍按既定清单继续。

## 当前入口与边界

`resolvedesk.app`的`POST /knowledge/search`（免费）、`DeskAgent`主检索与知识工具、`roles.build_it_tools`专业检索 → `DeskServices.search` → `ReliableRetrieval` → 同一`MCPToolManager`中的`it_rag`/`it_bm25` → 当前SQL/E5/Chroma。

| 要求 | 当前实现和验证 |
| --- | --- |
| 查询与工具TTL缓存 | 上层完整流水线缓存先于Flash改写/重排，Redis和有界进程缓存；下层原生工具缓存；同查询/身份/角色/选项再次执行不重复付费。默认只读MCP清单30秒缓存，按服务配置可禁用 |
| 权限、重导入、跨worker失效 | 指纹包含可见chunk、文档generation、owner/visibility、embedding身份和索引水位；同内容改ACL同样失效。缓存命中仍批量SQL复核，副本返回，防调用者污染缓存 |
| 独立超时与有界在途调用 | 原生RAG4秒、BM252秒，改写/重排各3秒；通用回退另有期限。异步取消可及时返回，同步线程超时后仍占名额；检索4个、词法2个线程名额，不无限堆积放弃的调用 |
| 熔断与恢复 | 原每进程closed/open/half_open机制接到原生RAG，默认5次失败/60秒等待；唯一半开探测，旧generation结果不能关闭新熔断。测试缩短等待参数以实际验证并发探测/恢复，不跳过状态转移 |
| 故障回退语义 | hybrid明确`degraded=true/effective_mode=bm25`，BM25失败返回不可用；显式vector故障保持vector请求语义，items为空，不以词法结果冒充向量。改写/重排故障保留原查询/RRF证据并记录错误 |
| 无知识依据时处理 | 完全知识故障且无证据时停止生成政策/排障答案，持久状态awaiting_input、错误knowledge_unavailable，保留问题，不自动创建工单 |
| 生成期间知识变更 | 每次主模型调用前、流式发送批次前、最终回答及安全交接前批量核验当前SQL引用；权限撤销/版本替换拦截后续批次和最终旧引用。此前已经合法发送的数据不能追溯回收 |
| 本地工具适用策略 | 纯函数诊断/字段核对保留Schema和白名单；即时业务SQL读使用当前鉴权及数据库statement/lock期限，不缓存业务状态或伪造回退；草稿、确认、审批等写事务不通过通用工具缓存/重试。写MCP仍禁用 |

正式技术选型仍为PostgreSQL、Redis、Chroma和本地E5，模型仅DeepSeek Flash，没有比较或接入专用重排模型。熔断统计是每进程状态，Redis共享缓存不代表全局共享熔断。
