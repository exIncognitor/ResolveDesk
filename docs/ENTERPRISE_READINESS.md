# 企业使用边界检查

2026-10-29 · 范围：当前 `resolvedesk.app` HTTP入口、Vue身份切换、知识权限、负反馈评测、业务状态机与服务端配置。

当前版本适合演示和验证企业IT服务流程。直接供真实企业生产使用仍有下述业务与身份设计缺口。本次为源码检查和针对性回归，未进行全仓库穷尽安全审计或生产渗透测试。

## 本次已修复

| 问题 | 修复与验证 |
| --- | --- |
| support可通过负反馈候选查看同租户他人的问题、回答和备注，还可将其转为评测样本 | `Store.regression_candidates` 与 `EvaluationService.promote` 同时限制tenant和owner；其他support也不能访问。旧的已转用样本保留，生产迁移前需人工核验其分享授权 |
| 员工界面隐藏MCP管理面板，但可直接请求连接管理状态 | `/mcp`、`/integrations/mcp`增加support校验；员工CLI返回权限提示，知识MCP的只读检索继续遵守原文档权限 |
| `/system`的知识数量来自全局统计 | 返回当前身份可读的知识数量，避免泄露其他租户或私人文档的数量 |
| 未被派单的支持人员也看到“开始/解决”动作 | `allowed_actions`按assignee过滤，后端继续校验；前后端动作一致 |

证据：`tests/test_enterprise_boundaries.py`覆盖员工、同租户同事、两个support和跨租户身份；既检查入口，也直接请求管理API和他人会话/转用接口。原有知识MCP、私有知识、工单幂等/并发、本人记忆、确认草稿等测试继续保留。

## 生产前必须补齐

| 优先级 | 现状与真实使用影响 | 建议落地方式 |
| --- | --- | --- |
| P0 身份生命周期 | `app.py`启动时读取本地`data/auth.json`；角色仅user/support，令牌无内建过期时间和即时撤销。离职、转岗和令牌泄露无法按企业流程立即处理 | 接OIDC/企业SSO；短时会话、服务端撤销与账号禁用；每次请求验证当前角色和租户。演示令牌不得用作企业共享账号 |
| P0 职责分离 | support同时承担业务审批、开通、知识发布、评测和全局Skills重载；没有独立系统管理员、部门主管或资源负责人。禁止自批并不等于获得了资源负责人的批准 | 拆分employee、approver、operator、knowledge_editor/reviewer、admin权限；审批绑定部门/资源和人员。把全局运行配置、密钥、重载与普通支持人员分离 |
| P0 真实执行一致性 | `BusinessService`、`licenses.py`明确模拟；权限开通只写`desk_grants`，维修与席位只改本地业务状态。不会真的操作企业目录、设备或供应商 | 引入目录/ITSM/资产/软件授权适配器；外部操作幂等键、outbox、超时后查询、回调验签和状态对账；外部确认成功后才标记fulfilled。上线前演练成功、失败、超时与重放 |
| P1 权限授予生命周期 | `desk_grants`为每人每资源一行，后续开通直接覆盖级别和到期时间；无权限撤销流程、授权来源合并、离职回收。过期只是查询时隐藏，不会撤销外部真实权限 | 将申请、批准、授予记录分开；按资源串行核验有效授权；设计续期、降级、撤销、失败补偿与定时对账 |
| P1 工单组织能力 | 模拟维修只能分派给当前support；无法派给其他值班人、跨组转交或处理人员离职/休假。资产与资源目录仍是显式演示数据 | 接租户内有效成员与班组目录；校验受派人资格，支持重分派与升级；明确处理人与验收人的分离、SLA和超期处理 |
| P1 数据与运维治理 | 会话、反馈、知识、评测和日志缺少完整企业保留/导出/删除流程；只读MCP能力声明不替代外部系统实际授权。当前本地Nginx无TLS，实例共用模型配置 | 明确数据分类、租户保留策略和备份恢复演练；外部连接按租户/调用人授权；公网入口TLS与限流；生产密钥使用秘密管理系统。移除累计费用上限后仍需并发和请求防滥用控制 |

## 已有边界与核验方法

- 会话、消息、轨迹与记忆按tenant+owner隔离；support能看租户工单，不代表能看私有聊天。评测作业按创建者隔离。
- 文档读权限、发布状态、版本和有效期由SQL权限来源决定；不能只靠向量检索结果或前端隐藏入口。
- 模型输出只能生成申请草稿；用户确认后才产生模拟工单。审批、预占、开通、派单与验收继续由服务端状态机检查，模型不授予角色。
- 业务操作保留版本冲突、幂等回执、事务与审计。两名操作员抢同一版本、重复确认、席位不足和资产重复维修均有回归覆盖。

建议下一阶段先做身份生命周期和职责分离，再接一个真实业务系统的测试环境；不应先扩大Agent数量。每一项以越权反例、外部失败补偿和可恢复的真实流程作为验收条件。
