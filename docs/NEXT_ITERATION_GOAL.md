# ResolveDesk 下一轮目标提示词

以下为本轮已建立目标的固定范围。Python为唯一后端，原Java学习实现不列为欠缺项。实际进度与证据另见NEXT_ITERATION_PROGRESS.md。

请为 ResolveDesk 创建并持续推进一个有明确边界的开发目标，完成开发、测试、部署和 GitHub 门禁后停止。

项目目录：
D:\desktop\实习\ResolveDesk

目标：
在已完成的 Python 技术迁移基础上，提升依赖安全、评测可信度、运行效率和软件授权业务深度。所有提升必须有实际代码、对照数据和验收证据。

一、固定范围和约束

1. Python 是唯一后端。原 Java 版本是另一套学习实现，不属于当前项目，不新增 Java 服务，不把未迁移 Java 列为缺项。
2. 沿用现有 Vue 前端，以及 PostgreSQL、Redis、Chroma、MCP、Prometheus、Docker 主技术栈。
3. 既有 G01–G13 迁移清单保持固定，本轮新增优化单独记录。
4. 只使用 deepseek-flash。读取当前唯一费用账本，沿用累计20元预算并保留2元余量；不得重置费用、恢复旧消费状态或使用不明来源的Key。
5. 专用重排模型比较继续不做；真实外部告警继续保留待验收，不发送外部通知。
6. 遵守项目AGENTS.md，使用Git检查点保护已有版本。保护数据库、凭据、模型、用户资料和已有工作。
7. 不为堆技术引入新框架或基础设施。替换选型必须有当前项目的实测瓶颈、同条件对照和维护成本依据。

二、工作包A：依赖安全与兼容升级

重新核对实际安装版本和官方安全公告，处理FastAPI、Starlette、python-multipart的已知上传解析问题。

选择相互兼容、覆盖已知修复的版本组合，固定经验证的依赖，并增加可重复的依赖安全检查。

验收应覆盖正常及异常上传、大小边界、鉴权、并发限制、SSE、MCP和应用启动关闭。异常输入测试使用隔离环境，不攻击正在使用的服务。

三、工作包B：独立质量评测

建立与现有开发集去重的固定留出集：
- 至少100条意图和检索用例，覆盖四类业务及歧义、跨域、拒答和错误码。
- 至少12组多轮对话，覆盖纠错、换任务、工具故障和业务状态变化。

明确标注人工编写、合成及其他合法来源，不冒充生产数据。留出集固定后，不因优化结果修改标签或评分标准。

使用任务开始时的已验收版本作为基线，在相同题目、知识和配置下比较：
- 意图Accuracy、Macro-F1；
- 检索Recall@K或MRR、引用有效性；
- 多轮任务与业务最终状态成功率；
- 延迟、模型调用次数、Token和费用。

以确定性断言为主要依据，Flash Judge作为辅助并说明偏差。免费测试先完成，真实模型验收按剩余预算安排。费用不足时明确报告未测项，不降低标准或伪造完成。

四、工作包C：检索与执行效率

先测量，再优化：

1. 优化BM25全量加载、缓存版本全量遍历等实际热点，保留跨进程失效、权限及文档版本复核。
2. 为适合的简单问题增加较短执行路径；复杂或低置信问题保留专家协作。
3. 按需触发查询改写、重排与二次生成，减少重复调用。
4. 检查异步请求链路中的同步数据库或CPU阻塞，仅修改有测量依据的瓶颈。

使用隔离的合成知识数据，在约1000和10000片段、并发1/5/10下测试，记录冷暖缓存、P50/P95、错误率和资源占用。

免费组件压测与真实模型耗时分别报告。只有质量不退化且收益有证据的优化，才作为默认路径。

五、工作包D：软件授权业务深化

将静态软件席位目录深化为可持久化的模拟业务流程：
申请→审批→席位预占→分配→撤销或到期回收。

实现权限控制、禁止自批、并发防超分配、幂等、版本冲突处理和审计。

Agent负责读取制度和实时目录、准备草稿、解释状态；审批和分配仍由获授权接口执行，不允许模型绕过确认。

保持现有权限申请、设备维修流程通过回归。所有业务数据明确标注为模拟。

六、交付和完成条件

每个工作包完成后提交检查点，记录：
修改内容、基线与新结果、测试证据、限制和恢复位置。

最终完成：
- 与改动风险相称的自动化和故障测试；
- 固定留出集的前后对照；
- 前端测试及构建；
- 宿主机与Docker入口部署验收；
- GitHub四项门禁通过；
- 文档、实际入口和运行配置一致。

不要把“代码已写”“测试通过”“效果提升”“生产可用”混为一谈。发现新问题时区分本轮必需修复与后续建议，不无限扩展目标。

当前范围全部验收后结束目标，汇报已完成项、实测收益、剩余限制、累计API费用和代码版本。
