## 已进入当前入口的能力

- `/eval/run` 直接测 `ITIntentRecognizer.recognize`，记录细粒度/业务域预测、Accuracy、Macro-F1、每类指标和三路来源覆盖。`eval_metrics.intent_report` 只归约实际预测，已经移除以 `business.classify` 冒充当前识别器的评测路径。
- 自定义数据可通过 `/eval/datasets` 创建、列表、按 ID 获取，或内联提交。数据归租户和作者本人所有，只有 support 可以操作；其他 support 也不能读取他人的数据。非 demo 租户必须显式提供评测集，不能自动套用 demo 知识。
- 数据集最多 200 条意图、100 段对话、每段 50 轮、100 项合成资产，规范化后不超过 1MB。支持逐轮 reference/evidence、会话分组、用户、预期意图/角色/状态、成功工具、实体和回答包含/排除断言。保存的数据集不可原地覆盖。
- 每轮都有独立 Judge、历史和当轮参考资料；前一轮不通过，即使最后一轮正确，整段仍然失败。执行/评分失败保留在全部请求的分母，另外给出有效结果通过率。意图和对话有分别口径，并增加 overall_pass_rate。
- 正式评测使用独立 PostgreSQL schema、Chroma 知识/私有记忆 collection、Redis namespace，不退回 SQLite。显式 SQLite 离线夹具仍可用于免费单元测试。知识仅复制调用者租户的共享片段，不把真实资产/工单或私有资料转授给模拟员工。业务资产来自显式合成夹具。
- 运行前冻结数据集、知识、引擎源码摘要及 embedding 身份。恢复使用同一沙盒和已完成结果；源码或 embedding 变更后拒绝继续旧作业，要求建立新作业。新报告使用active-quality-v2：数据/知识/评分配置/embedding/技术栈相同才具有相同基线指纹，代码身份单独记录，以便比较代码修改前后效果。历史v1报告和指纹保留，不自动跨指纹比较。
- PostgreSQL 队列锁统一限制跨 worker 的两个活动作业。当前非过期作业上限为全局 200、每租户 50；作者保存的数据集上限 50。单元结果上限 2MB、总报告 8MB、证据快照 20MB。达到上限会明确拒绝，不自动清空用户资料。
- 租约使用数据库时间、execution_epoch 与 heartbeat，进度、单元、快照和最终结果写入均检查所有权。陈旧 worker 不能提交新结果。
- 初次时限 1–3600 秒；用时跨进程持久保存，不因恢复归零。时限耗尽后需显式提供 extra_seconds，单次最多 3600 秒，作业终生最多 7200 秒。前端显示追加时间及恢复语义。
- 模型调用之前先记录单元 started。完成单元复用；中断单元只允许读取已有终态回执或事务幂等回执恢复。无法确认的付费步骤禁止自动重调；后续尚未开始的独立案例可继续。当前 Judge 明确只请求一次，保留旧兼容评测器默认两次的行为。
- 权限流程仍实际执行确认幂等、审批、模拟开通和有效授权核对；维修流程保留分诊、派单、处理、返工和验收状态核对。
- 已选基线受保护；人工可以选择完整执行、评分有效但未满分的报告作为真实基准。不会自动用新报告覆盖旧基线或以100%作为建立基线的前提。
- 增加免费保留预览和运维CLI：备份/摘要及覆盖核验、精确计划确认、SQL无CASCADE依赖检查、独立Chroma/Redis资源回收、失败重试、过期墓碑和容量释放。作者数据、已选基线、源业务和金融账本保留；归属不明的旧沙盒及离线文件夹具明确保护。见 `EVAL_RETENTION_OPERATIONS.md`。
